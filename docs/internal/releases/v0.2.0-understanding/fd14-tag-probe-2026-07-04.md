# FD-14 tag-quality probe (2026-07-04)

The v0.2.0 gate item that tests the product's foundational assumption: v1
extraction is FOLDER-FIRST (fields come from folder and file NAMES; embedded
tags play no role, per FD-14, superseding the discovery doc's
`preferSource=tags` default). This probe reads a bounded, deterministic,
strictly READ-ONLY sample of real embedded tags and measures whether that
assumption holds, or whether tags are materially MORE complete than folder names
and should reopen OQ-1.

**Verdict up front: the folder-first assumption HOLDS. Do NOT change the v1
default. F-303 keeps its default confidence weighting. OQ-1 is not reopened.**

## Probe design and sampling method

Generated by the ignored, feature-gated integration test
`tests/fd14_tag_probe.rs`:

```text
cargo test -p abo-core --features probe --test fd14_tag_probe -- --ignored --nocapture
```

- **Feature-gated, off by default.** The probe engine lives in
  `crates/abo-core/src/probe/` behind the `probe` Cargo feature, which is the
  only thing that pulls the optional `lofty` dependency. It is never in the
  default build or the shell: embedded-tag extraction as a real feature is
  F-1101, deferred past v1 (D-15/FD-03). This probe is a measurement instrument,
  not a shipped code path.
- **Read-only.** `probe::tags::read_tag_fields` opens each file through lofty's
  probe and reads the primary tag's title / artist / album / composer. Nothing
  is written, converted, or re-saved. No file under `E:\Books - Audio` was
  created, modified, renamed, or deleted (D-09).
- **Deterministic bounded sampling.** A fresh read-only scan yields the
  path-sorted audio entries; `probe::deterministic_sample_indices` takes every
  Nth (stride = total / cap) up to a cap of 300. With 13,652 audio files the
  stride is 45, so the sample is 300 files spread evenly across the whole
  library and is identical every run.
- **Comparison baseline.** For each sampled file the probe uses the folder-first
  title/author the product's own F-303 merge (`parse::extract`) computed for
  that same entry, so tags are compared against exactly what the product would
  use, not a re-derivation.

## Results (sample of 300 of 13,652 audio files)

Tag read wall time: 11.0 s for 300 files (lofty reads only each file's tag
header, not the whole audiobook).

### Readability

| Fact | Count | % of sample |
|---|---:|---:|
| lofty-readable | 297 | 99.0% |
| unreadable | 3 | 1.0% |
| had at least one usable tag | 292 | 97.3% |

### Tag field completeness

| Field | Present | % of sample |
|---|---:|---:|
| title | 255 | 85.0% |
| author (artist frame) | 289 | 96.3% |
| album (series-ish) | 287 | 95.7% |
| narrator (composer frame) | 89 | 29.7% |

### Folder-first completeness, same sample (for comparison)

| Field | Present | % of sample |
|---|---:|---:|
| folder-derived title | 300 | 100.0% |
| folder-derived author | 300 | 100.0% |

### Tag-vs-folder agreement (over files where BOTH sources have the field)

Agreement is case- and punctuation-insensitive, and counts a match when the
normalized values are equal or one meaningfully contains the other (so a tag
title carrying a subtitle the folder omits still agrees).

| Field | Comparable | Agree | Agreement rate |
|---|---:|---:|---:|
| title | 255 | 180 | 70.6% |
| author | 289 | 92 | 31.8% |

## Verdict (does folder-first hold?)

**Yes. Tags are NOT materially more complete than folder names; the folder-first
default stands.**

The decisive comparison is completeness: folder names carry a usable title AND
author for **100%** of the sample, while embedded tags carry a title for only
**85%** and an author for **96.3%**. On the one axis that could have reopened
OQ-1, whether tags are materially MORE complete than folder names, the answer is
the opposite: folder names are strictly more complete on both title and author.
The probe's mechanical trip-wire (tags exceed folder completeness by more than
15 percentage points on title or author) did not fire, so per this phase's risk
table the v1 folder-first default is unchanged and no OQ-1 reopen is raised.

Two secondary findings sharpen the picture and, if anything, reinforce
folder-first rather than undercut it:

1. **Low author agreement (31.8%) is a divergence-of-encoding signal, not a
   completeness signal.** When both a folder author and a tag artist exist, they
   disagree about two-thirds of the time. Spot-reading the sample, the cause is
   that the tag artist frame frequently encodes author differently from the
   folder name: `Lastname, Firstname` order, a combined `Author, Narrator`
   string, or, for a book deep inside a Hugo/Nebula collection, the individual
   book's author where the folder-first merge inherited the series/collection
   author from an ancestor. In other words, the two sources are not
   interchangeable; mixing them per-field would inject inconsistency. A single
   consistent source (folder names) is the safer v1 choice precisely because of
   this divergence. This is exactly the kind of signal F-303's confidence
   tiering exists to keep at bay: inherited author stays MEDIUM, never HIGH.

2. **Narrator tags are sparse (29.7%).** The composer frame carries a narrator
   for under a third of files, so tags are not a reliable narrator source in v1
   either. This corroborates deferring the tag reader (F-1101) rather than
   leaning on it now.

## Effect on F-303 (AC-303.3, G-08)

The verdict tunes the F-303 confidence weighting by CONFIRMING its default. The
`parse::extract::ConfidenceWeights` default (own-name => high, inherited =>
medium, derived => low) stands unchanged: folder names are the complete,
consistent source (100% title/author coverage), so own-name fields keep HIGH and
inherited fields keep MEDIUM. Nothing in the probe justifies demoting inherited
fields, and nothing justifies promoting a tag-derived source that this release
does not read. The tunable hook remains available for a future revisit if
F-1101 ever lands.

## Gate disposition

- **G-08**: satisfied. A bounded lofty subset read embedded tags on 300 real
  files, read-only, produced a field-completeness report, and this document
  records the written verdict: folder-first holds; F-303 keeps its default
  weighting.
- **OQ-1** (does the probe reopen `preferSource`?): **No.** Recorded here for
  jp's gate review; tags are not materially more complete, so the default is not
  reopened and tag-based extraction stays deferred to F-1101 (v1.1+).
